## Production integration law

A card family is a presentation adapter over canonical Atlas truth. It may not become a second scheduler, readiness engine, resource-state store, task type system, or result authority.

Every production card must preserve:

1. canonical task identity and assignment;
2. canonical execution warrant before result controls are exposed;
3. canonical result-return authority;
4. existing operation-specific result adapters where structured evidence is required;
5. real object/resource/state data rather than fixture labels;
6. one shared Worker navigation and completion/reopen contract.

4. **Sow** — port the approved bed-first lifecycle Trail, projections, and surprises grammar onto the existing production sowing Task Focus contract.
5. **Venue** — map real event/station/resource data into the approved two-method family: reminder/resource rows vs genuine execution checklist. Information such as station setup remains reusable context, not fake checklist work.
6. **Harvest, Water / Care, Check, Transplant** — move each family only after its live canonical reader and structured-result boundary are identified and regression-protected.

## Acceptance for each family

A family is mergeable only when:

- the live card renders from canonical data with no specimen constants;
- blocked/not-routed work exposes no completion control;
- an executable ordinary task opens directly to the real task card;
- structured-result work cannot quick-complete around its adapter;
- notes/problems route through the existing governed mutation boundary;
- completion remains complete after projection refresh;
- reopen/uncomplete still works where supported;
- Owner and Farm Hand surfaces do not disagree about execution truth;
- CI and production build are green.
